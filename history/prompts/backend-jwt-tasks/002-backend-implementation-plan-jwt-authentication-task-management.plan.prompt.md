For each phase, specify:

-------------------------------------------------------
SECTION 2: FOLDER STRUCTURE PLAN
-------------------------------------------------------

Define exact folder structure:

/apps/api/
├── main.py
├── core/
│   ├── config.py
│   └── security.py
├── db/
│   ├── session.py
│   └── models.py

└── services/task_service.py

For each file define:
- Purpose
- Functions/classes to implement
- Dependencies

-------------------------------------------------------
SECTION 3: DATABASE & ORM PLAN
-------------------------------------------------------

1. Setup async SQLModel engine using DATABASE_URL
2. Create async_sessionmaker
3. Define tables/models:
   - Task model (id, title, description, completed, user_id, timestamps)
4. Add indexes: user_id, completed
5. Ensure automatic timestamps
6. Create get_session() dependency

-------------------------------------------------------
SECTION 4: JWT AUTHENTICATION PLAN
-------------------------------------------------------

1. Implement get_current_user() dependency
2. Decode JWT using BETTER_AUTH_SECRET
3. Validate expiration
4. Extract user_id
5. Raise HTTP 401 on invalid/missing token
6. Enforce user_id filtering for all task queries
7. Integrate dependency with API routes

-------------------------------------------------------
SECTION 5: SERVICE LAYER PLAN
-------------------------------------------------------

Implement task_service.py:

- create_task(user_id, task_data)
- get_user_tasks(user_id, filters)
- update_task(user_id, task_id, task_data)
- toggle_task(user_id, task_id)
- delete_task(user_id, task_id)

Execution order:
1. create_task
2. get_user_tasks
3. update_task
4. toggle_task
5. delete_task

Ensure:
- user_id always passed
- exceptions raised if task not found
- database session used correctly

-------------------------------------------------------
SECTION 6: API ROUTES & DEPENDENCIES PLAN
-------------------------------------------------------

Define /api/tasks routes:

- GET /api/tasks → get_user_tasks
- POST /api/tasks → create_task
- PUT /api/tasks/{task_id} → update_task
- PATCH /api/tasks/{task_id}/toggle → toggle_task
- DELETE /api/tasks/{task_id} → delete_task

For each route:
- Attach get_current_user() dependency
- Validate ownership
- Return JSON success/error format
- Support optional query params (status, sort)

-------------------------------------------------------
SECTION 7: FRONTEND INTEGRATION PLAN
-------------------------------------------------------

1. Ensure CORS allows http://localhost:3000
2. Ensure JWT token is accepted in Authorization header
3. Match API response format to frontend expectations
4. Test all CRUD operations from frontend
5. Verify multi-user isolation

-------------------------------------------------------
SECTION 8: ERROR HANDLING PLAN
-------------------------------------------------------

1. Global exception handlers for:
   - HTTPException
   - ValidationError
   - JWT errors
   - Database errors
2. Ensure proper HTTP status codes
3. Hide internal stack traces
4. Return consistent JSON error format
